Guida per Windows

Guida per installare e avviare l'app su Windows e sul telefono

Questa guida non dà per scontato niente: nessuna riga di comando, nessun programma, nessun termine tecnico che non venga spiegato prima di usarlo. Se un passaggio non torna, fermati lì — il resto della guida presuppone che quel passaggio sia andato a buon fine.

Cosa faremo: installare sei programmi sul computer (una volta sola), scaricare il progetto, preparare il database, scrivere una o più chiavi segrete in un file, installare un'app sul telefono, e poi un comando solo ogni volta che vuoi riaprirla — sul telefono vero, non solo nel browser.

Prima di iniziare

Due cose da darti, prima che tu arrivi al Passo 10:

  1. Un invito su GitHub come collaboratore del progetto (arriva una email da GitHub — vai cliccato "Accept invitation").
  2. Una o più "chiavi" (stringhe di lettere e numeri), mandate in privato — per messaggio, non per email in chiaro se possibile. Non farci nulla finché non arrivi al Passo 10: tienile semplicemente da parte.

Ti servirà anche un telefono Android, per il Passo 11 — e che computer e telefono siano sulla stessa rete Wi-Fi quando arrivi al Passo 12 (stesso router: non funziona con i dati mobili del telefono, e non funziona se uno dei due è collegato a una VPN).

Tre cose da sapere prima di provarla, per non perdere tempo a chiederti se è un bug:

  • Nessun modello è ancora stato interrogato davvero — questo primo giro è anche il primo collaudo reale, quindi aspettati che qualche prompt vada ritoccato dopo averlo visto rispondere.
  • Il manichino 3D non è mai stato visto girare fuori da un browser: con questa guida lo provi per la prima volta su un telefono vero.
  • Non c'è ancora nessun account online: tutto gira sul computer di chi ha avviato l'app (Passo 12). Con Postgres configurato al Passo 9, l'armadio sopravvive ai riavvii — ma solo restando sullo stesso computer, che deve essere acceso quando l'app viene usata.
1

Installare Node.js

Node.js è il programma che fa girare la parte "app" del progetto.

  1. Vai su nodejs.org/en/download
  2. Il sito riconosce da solo che sei su Windows: clicca il bottone "Windows Installer"
  3. Si scarica un file tipo node-v22.x.x-x64.msi. Aprilo (doppio clic)
  4. Segui l'installazione cliccando Avanti su ogni schermata, poi Installa, poi Fine. Le impostazioni di default vanno bene, non c'è nulla da cambiare.
Verifica che abbia funzionato

1. Premi il tasto Windows, digita PowerShell, premi Invio — si apre una finestra blu (o nera) con del testo: è il terminale, il posto dove scriveremo dei comandi per tutta la guida.

2. Scrivi (o incolla) questo e premi Invio:

node -v

3. Deve rispondere con qualcosa tipo v22.14.0. Se invece dice "node non è riconosciuto...", chiudi PowerShell, riaprilo, e riprova — a volte serve un riavvio della finestra dopo un'installazione.

2

Installare Python

Python è il programma che fa girare la parte che parla con l'intelligenza artificiale.

  1. Vai su python.org/downloads
  2. Clicca il bottone giallo "Download Python 3.1x.x" (deve essere 3.12 o più recente — se il sito propone una versione più vecchia, cerca nella pagina "Looking for a specific release?" e scegli una 3.12.x o 3.13.x)
  3. Apri il file scaricato.
Attenzione, questo passaggio si salta facilmente e serve

Nella prima schermata dell'installer, in basso, c'è una casella "Add python.exe to PATH". Spuntala prima di cliccare "Install Now".

  1. Aspetta che finisca, poi "Close".
Verifica (in una finestra PowerShell nuova — chiudi quella vecchia e riaprine una)
python --version

Deve rispondere Python 3.12.x o simile. Se dice "non riconosciuto", quasi sempre è perché la casella di sopra non era spuntata: disinstalla Python da "Impostazioni → App", e reinstallalo rifacendo attenzione a quel passaggio.

3

Installare uv

uv è lo strumento che scarica i "pezzi" di cui Python ha bisogno per questo progetto.

  1. Apri PowerShell (tasto Windows → PowerShell → Invio)
  2. Incolla questo comando e premi Invio:
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  3. Aspetta che finisca (qualche secondo), poi chiudi e riapri PowerShell.
Verifica
uv --version

Deve rispondere con qualcosa tipo uv 0.11.x.

4

Installare Git per Windows

Serve solo per un pezzo che porta con sé, chiamato bash: è quello che permette di avviare l'app con un comando solo, al Passo 12, invece di doverne scrivere due ogni volta. Non dovrai mai scrivere un comando git — quello resta tutto dentro GitHub Desktop, al passo successivo.

  1. Vai su git-scm.com/download/win: il download parte da solo
  2. Apri il file scaricato (tipo Git-2.4x.x-64-bit.exe) e clicca Avanti su tutte le schermate, lasciando le impostazioni di default — non c'è nulla da cambiare
  3. Alla fine clicca "Install", aspetta, poi "Finish" (togli la spunta a "View Release Notes" se c'è, non serve)
Verifica che abbia funzionato

Chiudi tutte le finestre PowerShell aperte, riaprine una nuova, e scrivi:

bash --version

Deve rispondere con qualcosa tipo GNU bash, version 5.x. Se dice "non riconosciuto", riavvia il computer e riprova — a volte serve perché Windows aggiorni il PATH di sistema.

5

Installare GitHub Desktop

Questo è il programma con cui scarichi il progetto, senza dover imparare i comandi di Git.

  1. Vai su desktop.github.com
  2. Scarica e installa (doppio clic, poi segue da solo)
  3. Alla prima apertura, accedi con l'account GitHub con cui hai accettato l'invito al passo "Prima di iniziare"
6

Scaricare il progetto

  1. Apri GitHub Desktop
  2. In alto: File → Clone Repository
  3. Nella finestra che si apre, vai sulla scheda "GitHub.com" — dovresti vedere il progetto (si chiama wardrobe) nell'elenco. Selezionalo.
  4. In basso scegli dove salvarlo sul tuo computer (va benissimo lasciare quello proposto, es. C:\Users\TuoNome\Documents\GitHub\wardrobe) e ricorda questo percorso: ti servirà tra un attimo.
  5. Clicca Clone.
7

Aprire il terminale nella cartella del progetto

  1. Apri Esplora file (l'icona della cartella gialla nella barra in basso) e vai nella cartella dove hai clonato il progetto (Passo 6.4)
  2. Tieni premuto Shift e fai clic con il tasto destro dentro la cartella (non su un file, nello spazio vuoto)
  3. Scegli "Apri finestra PowerShell qui" (o su Windows 11, semplicemente "Apri nel terminale")

Da qui in poi, ogni comando di questa guida va scritto in questa finestra (o in una nuova aperta nello stesso modo, nella stessa cartella).

8

Installare i "pezzi" del progetto (una volta sola)

Nella finestra PowerShell aperta al Passo 7, scrivi ed esegui, uno alla volta (aspetta che ognuno finisca prima del successivo — il primo impiega qualche minuto):

npm install
npm run api:sync

Se durante npm install vedi righe gialle "warning" o messaggi grigi, va tutto bene: sono normali, non sono errori. Un errore vero è scritto in rosso e interrompe il comando.

9

Installare e preparare Postgres

Postgres è il database vero e proprio: il posto dove l'app salva davvero i capi, gli outfit e gli utenti, così che restino lì anche dopo aver spento il computer. L'installer che scarichi da postgresql.org mette su la macchina che tiene i dati — non ha una finestra per guardarci dentro. Per quello lo stesso installer porta con sé pgAdmin 4, un programma a parte che resta sul computer e che riuserai ogni volta che vorrai vedere cosa c'è salvato.

  1. Vai su postgresql.org/download/windows e scarica l'installer per Windows x86-64 (o apri direttamente il file postgresql-18...-windows-x64.exe se l'hai già scaricato)
  2. Aprilo e clicca Avanti fino alla schermata della password: qui l'installer chiede una password per l'utente postgres (il "superuser" del database). Scrivine una e salvala da qualche parte (un file di note, un gestore di password) — non è recuperabile facilmente se te la scordi, e ti servirà tra due passaggi.
  3. Sulla porta lascia il valore proposto, 5432
  4. Continua con Avanti fino a "Install", poi aspetta. Alla fine l'installer offre di aprire "Stack Builder": non serve, lascia la casella vuota e clicca "Finish".
Verifica che abbia funzionato

Premi il tasto Windows e digita pgAdmin 4: deve comparire tra i risultati. Aprilo — alla primissima apertura chiede di inventare una "master password" (è solo per pgAdmin, diversa da quella di postgres scelta sopra): scegline una e ricordala, ti servirà ogni volta che riapri pgAdmin.

Ora due cose da fare una volta sola, sempre dentro pgAdmin.

Creare il database

  1. Nel pannello a sinistra, apri Servers → PostgreSQL 18: la prima volta chiede la password scelta al punto 2 sopra (quella di postgres, non quella di pgAdmin)
  2. Clic destro su Databases → Create → Database…
  3. Nel campo "Database" scrivi wardrobe, lascia "Owner" su postgres, e nella scheda "Definition" controlla che "Encoding" sia UTF8 (di solito lo è già)
  4. Clicca Save
Password di postgres dimenticata

Capita spesso: l'installer la chiede una volta sola, veloce, e non resta scritta da nessuna parte. Se non hai ancora creato il database wardrobe (sei ancora a questo punto della guida), la strada più semplice è disinstallare e reinstallare — Pannello di controllo → Programmi e funzionalità → disinstalla "PostgreSQL 18" (accetta anche la rimozione della cartella dati, se proposta), poi riesegui lo stesso installer del punto 1 scrivendoti la password prima di cliccare Avanti. Se invece hai già dati da non perdere, la password si reimposta senza reinstallare modificando pg_hba.conf — chiedi a chi ti ha mandato questa guida.

Applicare lo schema

  1. Clic destro sul database wardrobe appena creato → Query Tool
  2. In Esplora file vai in wardrobe\services\api\migrations: dentro trovi sei file, numerati da 0001_schema.sql a 0006_utenti.sql
  3. Nella Query Tool di pgAdmin, apri il primo file (icona a forma di cartella, in alto) ed eseguilo (▶ oppure il tasto F5). Ripeti per gli altri cinque, nell'ordine dei numeri — 0002, poi 0003, e così via fino a 0006.
Se sbagli o rilanci un file per errore

Nessun danno: ogni file è scritto apposta per non fare nulla se la tabella che crea esiste già. Se qualcosa va storto puoi sempre riaprire e rieseguire tutti e sei i file, in ordine, senza pensarci.

Verifica che abbia funzionato

Nel pannello a sinistra, apri wardrobe → Schemas → public → Tables: dovresti vedere una decina di tabelle, tra cui capi e utenti. Se le vedi, il database è pronto — e pgAdmin resta anche il modo in cui guarderai dentro il database in futuro: stessa strada, poi tasto destro su una tabella → "View/Edit Data → All Rows".

Provider, API key, e perché paghiamo fal.ai

Prima di scrivere le chiavi al prossimo passo, tre parole che tornano spesso — vale la pena capirle una volta sola.

Provider è l'azienda a cui "affittiamo" il modello di intelligenza artificiale: chi legge le foto e propone gli outfit non è nostro, è un servizio a pagamento a cui l'app si collega. Il progetto ne tiene tre intercambiabili: Anthropic (Claude, quello di riferimento), OpenAI (GPT), e Google (Gemini). Sono intercambiabili per costruzione — cambiare provider costa un file di codice, non un mese di lavoro — proprio perché non vogliamo scoprire fra sei mesi di essere legati a uno solo.

API key è una password legata a un account che paga — il nostro, non il tuo — e su cui si accumula la spesa a consumo, un po' come un numero di carta di credito. Da qui le due regole che contano: non finisce mai in un file che va su GitHub (per questo vive in .env, che il progetto ignora apposta), e si scambia per un canale privato, mai per email in chiaro.

Il progetto chiede al modello due lavori distinti, e ogni chiave può servire per l'uno, per l'altro, o per entrambi: leggere una foto (capire tipo, colore, tessuto di un capo) e proporre un outfit (scegliere cosa abbinare e spiegare perché). Quale provider fa quale lavoro si sceglie dalla schermata Modelli in uso, di cui parliamo dopo il Passo 12.

fal.ai non è un provider di linguaggio: è un servizio a parte che serve solo a "staccare" il capo fotografato dallo sfondo, come nelle foto di un catalogo online. Non è indispensabile — se manca quella chiave l'app funziona lo stesso, le foto restano semplicemente con lo sfondo originale. Ma un capo già isolato è anche più facile da leggere per il modello che lo analizza, quindi quando c'è aiuta anche il primo lavoro.

10

Scrivere le chiavi

  1. In Esplora file, entra nella cartella services, poi api (quindi: wardrobe\services\api)
  2. Trova il file .env.example (se non lo vedi, in alto in Esplora file clicca "Visualizza" → spunta "Estensioni nome file" e "Elementi nascosti")
  3. Copialo (clic destro → Copia, poi clic destro nello spazio vuoto → Incolla)
  4. Rinomina la copia (che si chiamerà tipo .env.example - Copia) in .env — attenzione: il nome deve essere esattamente .env, niente prima e niente dopo, nemmeno .env.txt
  5. Apri .env con il Blocco Note (clic destro → Apri con → Blocco note)
  6. Vedrai alcune righe che finiscono con =, una per ogni chiave possibile (ANTHROPIC_API_KEY, OPENAI_API_KEY, GOOGLE_API_KEY, FAL_KEY). Compila solo le righe per cui hai ricevuto una chiave, incollandola subito dopo il segno = (senza spazi, senza virgolette). Le righe per cui non hai ricevuto nulla lasciale vuote così come sono: l'app funziona comunque, semplicemente quel provider resterà spento finché non gli darai una chiave.
  7. Più in basso trova la riga #DATABASE_URL=host=localhost port=5432 dbname=wardrobe user=wardrobe password=wardrobe: togli il # iniziale e cambia user e password con quelli veri — user=postgres e la password scelta al Passo 9. Deve diventare una riga tipo DATABASE_URL=host=localhost port=5432 dbname=wardrobe user=postgres password=LA-TUA-PASSWORD
  8. Subito sotto trova #CARTELLA_FOTO=./dati/foto e togli anche qui il # iniziale — DATABASE_URL da solo salva già i capi nel database, ma senza questa riga le loro foto resterebbero solo in memoria e sparirebbero a ogni riavvio
  9. Salva (Ctrl+S) e chiudi il Blocco Note.

Questo file resta solo sul tuo computer: non finisce mai su GitHub (è scritto apposta per essere ignorato).

11

Installare Expo Go sul telefono

L'app, mentre è in sviluppo, non gira come un'app scaricata dal Play Store: gira dentro Expo Go, un'app-contenitore gratuita che carica il progetto in tempo reale dal tuo computer. È così che si prova un'app prima che sia pronta per essere pubblicata davvero.

Perché non lo trovi (ancora) aggiornato sul Play Store

Il progetto usa una versione di Expo (la "57") troppo recente per essere già arrivata sulla versione pubblica di Expo Go sul Play Store — capita spesso con un progetto in sviluppo attivo, non è un problema nostro. La soluzione è scaricare quella versione precisa direttamente dal sito di Expo, la stessa azienda che pubblica l'app sul Play Store.

  1. Sul telefono (non sul computer), apri il browser e vai su:
    expo.dev/go?sdkVersion=57&platform=android&device=true
  2. Nella pagina, tocca il link per scaricare il file Expo-Go-57.0.2.apk (o la versione 57.x più recente indicata)
  3. Quando il download finisce, tocca il file scaricato per installarlo. Android probabilmente avviserà con qualcosa come "Non è consigliabile installare app da fonti sconosciute" — è il messaggio standard per qualunque app scaricata fuori dal Play Store, anche quando è legittima come questa: tocca "Impostazioni", poi attiva "Consenti da questa fonte" per il browser che hai usato, torna indietro e installa.
  4. Apri Expo Go una volta, giusto per farla partire. Non serve creare un account né accedere con nessuna email.
Verifica che abbia funzionato

L'icona di Expo Go compare tra le app del telefono, e aprendola vedi una schermata con un bottone per scansionare un codice QR. La useremo al Passo 12.

12

Avviare tutto con un comando solo

Controlla prima che telefono e computer siano sulla stessa rete Wi-Fi (stesso router — non funziona se il telefono è sui dati mobili, o se uno dei due ha una VPN attiva). Poi torna alla finestra PowerShell del Passo 7 (quella nella cartella principale wardrobe, non dentro services\api) e scrivi:

npm run dev:app

Un comando solo, ma fa tutto in ordine: controlla Postgres, applica le migrazioni mancanti, avvia il "cervello" dell'app (le sue righe sono marcate [api]), aspetta che risponda, e alla fine mostra un codice QR — da lì in poi il terminale è di Expo.

  1. Aspetta una riga tipo API di Wardrobe in ascolto sulla porta 8787 — capi su Postgres — se dice invece capi su memoria (si azzera al riavvio), il .env del Passo 10 non ha DATABASE_URL attiva: fermati e controlla quella riga
  2. Subito dopo compare un riquadro fatto di quadratini: è il codice QR
  3. Sul telefono, apri Expo Go, tocca "Scan QR code", e punta la fotocamera sul codice nel terminale
  4. Dopo un po' (la prima volta può metterci un minuto o due) l'app si apre da sola sul telefono
Se Windows chiede il permesso

La prima volta possono comparire fino a due avvisi "Windows Defender Firewall ha bloccato alcune funzionalità di questa app" — uno per Python, uno per Node.js. Per entrambi: spunta sia "reti private" sia "reti pubbliche" e clicca "Consenti l'accesso". Controlla anche che la rete Wi-Fi risulti "Privata" e non "Pubblica" (Impostazioni → Rete e Internet → Wi-Fi → proprietà della rete): su una rete pubblica Windows blocca la connessione anche dopo aver detto "Consenti l'accesso". Senza questi due, l'app parte sul computer ma il telefono non la raggiunge — è quasi sempre questa la causa quando l'app resta bloccata dopo aver scattato una foto.

Importante: lascia questa finestra aperta finché usi l'app. Un solo Ctrl+C ferma API ed Expo insieme, in ordine, senza lasciare nulla acceso per sbaglio. Postgres invece resta acceso anche dopo: non costa nulla tenerlo su, e spegnerlo interromperebbe un'altra finestra che lo sta usando.

Vuoi solo dare un'occhiata rapida dal computer, senza toccare il telefono? Apri due finestre invece di una — npm run api:local nella prima, npm run mobile:web nella seconda — e si apre una scheda del browser con l'app. Comodo per guardare in fretta, ma la fotocamera vera — e il modo in cui l'app si sentirà per davvero — si provano solo sul telefono.

Come si usa, in breve

  • Aggiungi (in basso): scatta una foto o scegline una dalla galleria di un capo di vestiario. Aspetta che venga letta — vedrai categoria, colore, tessuto proposti. Se qualcosa è scritto su sfondo corallo/arancione, il modello non ne è sicuro: toccalo per correggerlo.
  • Il tuo armadio: tutti i capi aggiunti.
  • Chiedi a Wardrobe: scrivi qualcosa tipo "Fa caldo, sto per uscire, cosa mi metto?" e aspetta la risposta.

Provare un provider diverso

Con più di una chiave scritta al Passo 10, puoi scegliere quale modello legge le foto e quale propone gli outfit, senza toccare codice:

  1. Nell'app, vai su Profilo → Sviluppo → Modelli in uso
  2. Trovi due liste separate — Lettura foto e Suggerimenti — perché sono i due lavori distinti di cui parlavamo prima del Passo 10, e puoi assegnare un provider diverso a ciascuno
  3. Predefinito del backend è la prima voce di ogni lista: torna a quello scritto nel .env, se mai vuoi annullare la scelta
  4. Ogni modello mostra pronto o senza chiave — è la stessa cosa scritta al Passo 10: senza una riga compilata in .env, quel provider resta spento e sceglierlo darebbe un errore
Una cosa da sapere

Il .env si rilegge solo riavviando la finestra del Passo 12 (npm run dev:app, o npm run api:local se usi le due finestre separate). Se aggiungi o cambi una chiave, chiudi e riesegui il comando prima di aspettarti che l'app la veda.

C'è anche una schermata Playground modelli, sempre sotto Sviluppo: è un banco di misura, non una chat — serve a confrontare un modello con un altro su latenza, costo e qualità della risposta, un test alla volta, senza spostare la scelta stabile delle due liste sopra. Lì vedrai anche gpt-5.1 e gemini-2.5-pro: sono i nomi indicati nel documento di design, non ancora confermati sui listini ufficiali — se un provider risponde con un errore sul nome del modello, è il primo posto da controllare, e si corregge scrivendo MODELLI_OPENAI o MODELLI_GOOGLE nel .env, senza toccare codice.

Le prossime volte (versione corta)

Non serve rifare i Passi 1-11. Ogni volta che vuoi riaprire l'app:

  1. Apri PowerShell nella cartella del progetto (Passo 7), scrivi npm run dev:app, e scansiona il nuovo codice QR con Expo Go quando compare (Expo Go tiene anche una cronologia dei progetti recenti in home, ma se il computer ha cambiato indirizzo di rete dall'ultima volta, ripartire dal QR è la strada più sicura)
Una cosa da sapere

Con Postgres configurato al Passo 9, l'armadio resta quello di prima a ogni riavvio: capi, outfit e utenti vivono nel database sul computer, non nella memoria del programma. L'unico requisito è che sia lo stesso computer — i dati non vanno da nessuna altra parte, non c'è un cloud dietro. E se nel frattempo è arrivata una migrazione nuova con un git pull, npm run dev:app la applica da solo: non serve tornare in pgAdmin.
